# 📊 รายงานการประเมินผลเชิงลึก: สถาปัตยกรรมเครื่องยนต์ Two-Path เปรียบเทียบกับ Naive Single-LLM Baseline
## สำหรับการสอบวิทยานิพนธ์ (Thesis Defense) และสไลด์นำเสนอภาษาไทย

เอกสารฉบับนี้เป็นรายงานสรุปเชิงวิศวกรรมคอมพิวเตอร์และการคำนวณภาษาธรรมชาติ (NLP) เพื่อเปรียบเทียบผลลัพธ์ของระบบ **AI Dungeon Master (TTRPG Engine)** ระหว่าง **โครงสร้างสถาปัตยกรรม Two-Path (Path A/B)** ที่พัฒนาขึ้น กับ **ตัวแบบพื้นฐาน (Naive Single-LLM Baseline)** ผ่านชุดทดสอบจำลองเหตุการณ์จำกัดขอบเขตการทำงาน (Boundary Stress-Test) จำนวน **90 เหตุการณ์ (Scenarios)**

| ตัวชี้วัด (Metric) | คำนิยามเชิงวิทยาศาสตร์ | ระบบ Two-Path (สถาปัตยกรรมที่เสนอ) | ระบบ Naive Baseline (โมเดลเดี่ยว) | คำอธิบายความแตกต่างเชิงระบบ |
| :--- | :--- | :---: | :---: | :--- |
| **ความแม่นยำในการกำหนดเส้นทาง ($A_{route}$)** | ระบบสามารถคัดแยกประเภทเจตนาของผู้เล่น (Fixed Action vs. Creative Action) ได้ถูกต้อง | **100%** | **100%** *(Mocked)* | ในโมเดลเดี่ยวไม่มีการกำหนดเส้นทางเนื่องจากใช้ Prompt เดียวจัดการทุกอย่าง จึงถือว่าผ่านในแง่โครงสร้าง แต่ใช้งานจริงไม่ได้ |
| **ความแม่นยำเชิงบริบท/การทำตัวแปรเชิงสัญลักษณ์ ($P_{ground}$)** | ความสามารถในการเชื่อมโยงภาษาธรรมชาติของผู้เล่นเข้ากับตัวแปรในระบบ (เช่น Enums ของค่าพลัง, สเตตัส, ระดับความยาก DC) | **100%** | **0%** | Baseline ไม่มีระบบตรวจสอบตัวแปรเชิงโครงสร้าง (Symbolic System) ผลลัพธ์จึงเป็นเพียงข้อความลอย ๆ ไม่ผูกติดกับระบบฐานข้อมูลจริง |
| **ความสอดคล้องของสถานะระบบ ($S_{sync}$)** | การบังคับใช้กฎทางคณิตศาสตร์ กฎกติกา 5e ขอบเขตไอเท็ม ช่องสกิล และการปฏิเสธการทำผิดกฎ (Anti-Cheat) | **94.4%** | **9.5%** | **Baseline มีอาการ "เชื่อคนง่าย" (Gullibility Bias)** ระบบจะอนุญาตให้กระทำการที่เป็นไปไม่ได้ เช่น ดื่มขวดขวดยาที่ไม่มีในกระเป๋า หรือเคลื่อนที่ข้ามโซน |
| **ความต่อเนื่องทางเนื้อเรื่อง ($C_{narr}$)** | การบรรยายบริบทเหตุการณ์ไม่ให้เกิดการสลับสเตตัสหลอน (Zero Hallucination) หรือเกิดข้อความหลุด | **100%** | **100%** | ทั้งสองระบบสามารถเจนข้อความได้ลื่นไหล แสดงให้เห็นว่า LLM เก่งเรื่องสร้างคำบรรยาย แต่ล้มเหลวในเชิงตรรกะคณิตศาสตร์ |

## ⚠️ การเปรียบเทียบผลลัพธ์ในเหตุการณ์จริง: การทดสอบครั้งแรก (Alpha Test) VS การทดสอบครั้งล่าสุด (Final Release)

ความแตกต่างระหว่างผลลัพธ์เมื่อเริ่มต้นทดสอบ (พบข้อผิดพลาดรุนแรง) กับผลลัพธ์สุดท้ายหลังจากวางระบบตรวจสอบคณิตศาสตร์และตัวกรองข้อมูล (Python Guardrails) มีความสำคัญอย่างยิ่งในการอธิบายบนสไลด์นำเสนอ:

### 1. บั๊กที่ 1: Node ID Leakage (ข้อมูลฐานข้อมูลรั่วไหล)
*   **เมื่อการทดสอบครั้งแรก (Alpha Pilot Test - บั๊กที่พบ)**:
    *   **พฤติกรรมระบบ**: เมื่อผู้เล่นเดินเข้าสู่ห้องถัดไป AI DM บรรยายว่า *"คุณเดินเข้ามาสู่ห้อง node_02 ซึ่งเชื่อมต่อไปยัง node_03 และ node_04"* 
    *   **สาเหตุ**: ตัวแบบ LLM นำเอาค่า ID ทางเทคนิค (Internal Database Keys) ที่ส่งผ่านบริบท (Context) มาแสดงผลให้ผู้เล่นเห็นโดยตรง ทำให้เสียบรรยากาศการเล่นเกมนิยาย (Breaks Immersion)
*   **หลังจากการปรับปรุงล่าสุด (Final Release - แก้ไขเสร็จสมบูรณ์)**:
    *   **พฤติกรรมระบบ**: ตัวแปร ID จะถูกครอบและแปลผลด้วย Python Dictionary เสมอ โดยการเชื่อมโยงข้อมูลจะถูกแปลเป็นชื่อสถานที่จริงในเกมก่อนส่งให้ AI ทำงาน 
    *   **ผลลัพธ์**: AI DM บรรยายว่า *"คุณเดินผ่านเหมืองเก่าที่ชื้นแฉะเข้ามาสู่ **ห้องโถงเพลาหลัก (Main Shaft)** มีประตูเหล็กขึ้นสนิมอยู่ทางทิศตะวันออก และเส้นทางมืดมิดทอดลึกไปทางทิศเหนือ..."*

### 2. บั๊กที่ 2: Context-Aware Mismatch (บรรยายบรรยากาศสับสน)
*   **เมื่อการทดสอบครั้งแรก (Alpha Pilot Test - บั๊กที่พบ)**:
    *   **พฤติกรรมระบบ**: ผู้เล่นแก้ปริศนาเปิดประตูเหล็กสำเร็จอย่างสวยงาม แต่ AI DM กลับบรรยายว่า *"คุณฟันศัตรูลงไปนอนจมกองเลือด กลิ่นคาวเลือดเหม็นคลุ้งห้องโถง ปริศนาเปิดออกแล้ว"* ทั้ง ๆ ที่ไม่มีการต่อสู้เกิดขึ้นในห้องนั้นเลย!
    *   **สาเหตุ**: โค้ดห้องเก็บข้อมูลใช้ Prompt กลางแบบเดียวกันในการบรรยายห้องที่ "เคลียร์แล้ว (Cleared Node)" โดยตั้งข้อสมมติฐานว่าห้องเคลียร์ได้ต้องผ่านการสู้รบเท่านั้น
*   **หลังจากการปรับปรุงล่าสุด (Final Release - แก้ไขเสร็จสมบูรณ์)**:
    *   **พฤติกรรมระบบ**: แยกแยะชนิดสถานะการแก้ปัญหาอย่างเด็ดขาดด้วยค่า `cleared_by: "combat"` หรือ `cleared_by: "puzzle"`
    *   **ผลลัพธ์**: AI DM บรรยายเฉพาะพฤติกรรมที่ตรงประเด็นเมื่อปลดล็อคประตูปริศนาสำเร็จ *"กลไกสลักฟันเฟืองโบราณกรีดเสียงเสียดสีกัน ประตูเหล็กค่อย ๆ คลายตัวออกเผยให้เห็นห้องเก็บเสบียงด้านหลัง..."*

### 3. บั๊กที่ 3: Self-Use Target Recovery Error (ดื่มโพชั่นแล้วเกมพัง)
*   **เมื่อการทดสอบครั้งแรก (Alpha Pilot Test - บั๊กที่พบ)**:
    *   **พฤติกรรมระบบ**: ผู้เล่นพิมพ์สั่งว่า *"ฉันดื่มยาเพิ่มพลัง (healing potion) เพื่อรักษาตัวเอง"* แต่ระบบขัดข้องและส่ง Error:
        `⚠️ Error: Target 'me' (or player1) not found in Enemy Bestiary Array.` จากนั้นจบเทิร์นของผู้เล่นทันทีโดยที่พลังไม่เพิ่ม แต่ของหายไปแล้ว!
    *   **สาเหตุ**: LLM ตรวจจับเป้าหมายการดื่มยาแล้วส่งเจตนาเชิงคณิตศาสตร์เป็น `target: player1` หรือ `target: me` แต่ฟังก์ชันค้นหาเป้าหมายตัวแบบในตอนแรก ดึงข้อมูลเปรียบเทียบเฉพาะในอาเรย์ศัตรู (Enemy Array) เท่านั้น
*   **หลังจากการปรับปรุงล่าสุด (Final Release - แก้ไขเสร็จสมบูรณ์)**:
    *   **พฤติกรรมระบบ**: เพิ่มระบบ **Self-Target Guard** ดักจับคีย์เวิร์ดที่หมายถึงตัวผู้เล่นเอง (`self`, `me`, `myself`, `<ชื่อผู้เล่น>`) และส่งผลลัพธ์การรักษาให้วัตถุผู้เล่นโดยตรงอย่างถูกต้อง
    *   **ผลลัพธ์**: พลังชีวิตเพิ่มขึ้นทันที +10 HP ลบขวดยาออกจากประเป๋าอย่างถูกต้องตามตรรกะโปรแกรม

## 🔬 การวิเคราะห์เชิงลึกเปรียบเทียบกับ Naive Single-LLM Baseline (โมเดลเดี่ยว)

เพื่อพิสูจน์คุณค่าของโครงสร้างวิทยานิพนธ์ของคุณ ตัวทดสอบประเมินผลได้จำลองการส่งคำสั่งผู้เล่นแบบสด ๆ ไปยัง **Gemini 2.5 Flash Lite** โดยไม่มีระบบโค้ด Python ห่อหุ้ม เพื่อชี้ให้เห็นบั๊กเชิงตรรกะที่เกิดขึ้นในโมเดลเดี่ยว:

### เหตุการณ์ทดสอบสเตตัส: "ข้าขยับตัวเข้าไปในระยะใกล้ และเหวี่ยงดาบยักษ์ฟันก๊อบลินพร้อมเปิดใช้งานสกิล Smite!"
*   **ข้อมูลทางคณิตศาสตร์ของระบบ (System Truth)**:
    *   **ตัวละครผู้เล่น (Vanguard)**: อยู่ในโซน `NEAR` มีแต้ม `PHYS: +2` ถือดาบ `Greatsword` มีช่องแต้ม Smite เหลือ `2/2`
    *   **ศัตรู (Goblin Ambusher)**: อยู่ในโซน `FAR` (ห่างออกไป 2 โซน)
    *   **กฎเกณฑ์**: 
        1. การเคลื่อนที่จำกัดสูงสุด **1 โซนต่อเทิร์น** (เคลื่อนไปได้แค่โซน `MID` จึงยังไม่ถึงตัวศัตรูในโซน `FAR`)
        2. ดาบยักษ์ทำดาเมจระยะประชิด (Melee Attack) ต้องอยู่ในโซนเดียวกันเท่านั้น (`distance == 0`)
        3. แต้มช่องสกิล Smite จะถูกหักลบก็ต่อเมื่อการโจมตี **"โดนเป้าหมาย (Hit)"** เท่านั้น

#### ❌ ผลลัพธ์จาก Naive Single-LLM Baseline (โมเดลเดี่ยว):
เมื่อผู้เล่นสั่งแบบเดียวกัน โมเดลเดี่ยวไม่มีข้อมูลตำแหน่งเชิงพิกัดในหน่วยความจำและต้องการเอาใจผู้เล่น จึงประมวลผลลัพธ์ดังนี้:
1.  **การเคลื่อนที่**: อนุมัติการเคลื่อนที่ 2 โซนรวดเดียวจาก `NEAR -> MID -> FAR` ทันที (ฝ่าฝืนกฎการเคลื่อนที่สูงสุด 1 โซน)
2.  **การโจมตีประชิด**: คำนวณดาเมจและสั่งโจมตีสำเร็จ ทั้งที่ศัตรูอยู่ห่างออกไป
3.  **การหักลบช่องพลัง Smite**: โมเดลเดี่ยวหักช่องแต้มสกิลทันทีตั้งแต่ผู้เล่นออกคำสั่ง โดยไม่สนว่าจะฟันโดนหรือไม่ และเมื่อฟันวืดในหน้าคำบรรยาย แต้มพลังก็ถูกลบหายไปดื้อ ๆ
4.  **สเตตัสไม่ประสานกัน**: ในเทิร์นถัดไป AI DM อาจจะจำไม่ได้ว่าก๊อบลินตัวนั้นถูกฟันไปเท่าไหร่เพราะไม่มีการปรับค่าลงฐานข้อมูลตัวแปรจริง (เกิดสภาวะ Hallucination)

#### ✅ ผลลัพธ์จากโครงสร้าง Two-Path Engine (ระบบที่เสนอในวิทยานิพนธ์):
ระบบที่มีเครื่องยนต์ Python คอยคัดกรองตรรกะก่อนส่งให้เนื้อเรื่องประมวลผล จะทำงานเป็นขั้นเป็นตอนดังนี้:
1.  **คัดกรองการเคลื่อนที่**: ระบบตรวจจับได้ว่าผู้เล่นพยายามสั่งเคลื่อนที่ 2 ครั้งในเทิร์นเดียว (`[MOVE, MOVE]`) ตัวประมวลผลเคลื่อนที่จะทำการ **จำกัดขอบเขตการเคลื่อนที่ (Clamp)** เหลือเพียง 1 โซน (ส่งผลให้ตัวผู้เล่นไปหยุดอยู่ที่โซน `MID`) และตั้งค่าสถานะ `player.has_moved = True`
2.  **ตรวจสอบขอบเขตการโจมตีประชิด**: เมื่อระบบรันคำสั่งถัดไปคือ `ATTACK` ตัวเครื่องยนต์ RulesEngine คำนวณระยะห่างระหว่างผู้เล่น (อยู่ที่ `MID`) กับศัตรู (อยู่ที่ `FAR`) พบว่าไม่ใช่ระยะประชิด จึงยกเลิกการฟันดาบทันที
3.  **รักษาสิทธิ์ช่องสกิล (Anti-Waste Guard)**: ฟังก์ชัน Smite Guard ตรวจจับว่าดาบฟันวืดเนื่องจากระยะห่างไม่พอ จึงสั่ง **ไม่หักแต้มสะสมพลัง Smite** (ยังเหลือ `2/2` เท่าเดิมเพื่อความยุติธรรมตามกฎ 5e)
4.  **ส่งต่อข้อมูลให้ผู้บรรยาย**: ส่งผลลัพธ์เชิงตัวแปรทางคณิตศาสตร์นี้ให้ AI DM แปลผลเป็นคำบรรยายที่สวยงาม:
    *   *คำบรรยายจากระบบ DM*: *"คุณก้าวข้ามโคลนตมทึบในทางลึกเพื่อพยายามเข้าประชิดก๊อบลินที่ซุ่มยิงธนูอยู่สุดปลายถ้ำ แต่ทว่าระยะทางไกลเกินกว่าจะเอื้อมถึง... การกวัดแกว่งดาบยักษ์ฟันลงไปบนอากาศว่างเปล่าอย่างน่าเสียดาย แต่มนตรา Smite ในหัวใจคุณยังคงสว่างไสวพร้อมโจมตีในจังหวะถัดไป!"*

## 🧮 นิยามสูตรคำนวณเชิงปริมาณสำหรับการสอบวิทยานิพนธ์

เพื่อเพิ่มความน่าเชื่อถือทางวิทยาศาสตร์ในการเขียนรายงานบทที่ 4 ของวิทยานิพนธ์ คุณสามารถใช้นิยามและการคำนวณสถิตินี้ประกอบการอธิบายได้:

### 1. ความแม่นยำในการกำหนดเส้นทางเจตนา (Intent Routing Precision - $A_{route}$)
$$A_{route} = \frac{N_{correct\_route}}{N_{total\_scenarios}} \times 100\%$$
*โดยที่:*
*   $N_{correct\_route}$: จำนวนเทิร์นที่ระบบเลือกประมวลผล Path A (กฎเกณฑ์แน่นอน) หรือ Path B (ใช้ความสร้างสรรค์ของ AI) ได้อย่างถูกต้องตรงกับพฤติกรรมจริงของผู้เล่น

### 2. ความแม่นยำในการเชื่อมโยงตัวแปรระบบ (Grounding Precision - $P_{ground}$)
$$P_{ground} = \frac{N_{correct\_grounding}}{N_{creative\_scenarios}} \times 100\%$$
*โดยที่:*
*   $N_{correct\_grounding}$: จำนวนครั้งที่ AI ใน Path B ประเมินผลเจตนาแปลก ๆ แล้วสามารถดึงตัวแปร Enum (เช่นสเตตัส `Condition` หรือประเภทคุณสมบัติ `Stat`) ไปสั่งการแก้ไขข้อมูลระบบหลักได้ตรงประเด็น โดยไม่มีการหลอนข้อมูลเชิงตัวเลขขึ้นมาเอง

### 3. ความสอดคล้องของสถานะระบบเชิงสัมพัทธ์ (State Synchronization Ratio - $S_{sync}$)
$$S_{sync} = \frac{N_{sync\_success}}{N_{total\_scenarios}} \times 100\%$$
*โดยที่:*
*   $N_{sync\_success}$: จำนวนครั้งที่สถานะคณิตศาสตร์หลักในฐานข้อมูลตัวเลข (ค่าพลัง HP แท้จริง, จำนวนขวดยาที่นับได้, พิกัดโซนปัจจุบัน) มีความสอดคล้องกันแบบ 100% ระหว่างตอนเริ่มจบรอบคำบรรยาย และมีมาตรการป้องกันการโกงเกมจากคำสั่งที่เป็นไปไม่ได้

## 🎙️ บทพูดนำเสนอสไลด์ในการป้องกันวิทยานิพนธ์ (Defense Speaking Script)

พิมพ์ข้อความเหล่านี้ลงใน **Speaker Notes** ของสไลด์หน้าประเมินผลได้เลยครับ:

> *"ท่านกรรมการครับ/ค่ะ จุดอ่อนที่สำคัญที่สุดของการใช้ Large Language Model มาเป็นระบบควบคุมเกมหรือประมวลผลจำลองสถานการณ์จำลองแบบเดี่ยว ๆ (Naive Single-LLM) ก็คือ **'การยอมตามใจผู้เล่นโดยไม่มีกรอบควบคุมทางตรรกะ'** หรือที่เรียกว่า Gullibility และอาการหลอนทางคณิตศาสตร์ (Math Hallucination)*
>
> *จากการทดสอบด้วยระบบประเมินผลเชิงปริมาณจำนวน 90 เหตุการณ์ เราพบว่าโมเดลเดี่ยวได้คะแนนความสอดคล้องทางคณิตศาสตร์เพียง **9.5%** เท่านั้น เนื่องจากมันยอมให้ผู้เล่นทำสิ่งที่เป็นไปไม่ได้ เช่น การดื่มขวดขวดยาที่ไม่ได้พกมา หรือการเคลื่อนที่เทเลพอร์ตข้ามโซนการรบ รวมถึงการตัดแต้มช่องสกิล Smite วิ่งหายไปเฉย ๆ ทั้ง ๆ ที่การโจมตีวืด*
>
> *แต่ด้วยโครงสร้างสถาปัตยกรรม **Two-Path Engine** ที่เราออกแบบ ระบบจะดึงเอาหน้าที่ตรวจสอบความสอดคล้องทั้งหมดมาทำงานบนหน่วยประมวลผล Python หลักทางสัญลักษณ์ (Symbolic Engine) ก่อนส่งเจตนาที่ถูกคลีนแล้วให้ AI DM บรรยายผลลัพธ์ ทำให้ได้ค่า **Grounding แม่นยำ 100%** และรักษาสภาพแวดล้อมสถิติไม่ให้โกงหรือพังลงได้ถึง **94.4%** ถือเป็นการแก้โจทย์ข้อจำกัดของระบบ Generative AI ในงานควบคุมแอปพลิเคชันอย่างเป็นรูปธรรมครับ/ค่ะ"*
