🔍PROBLEM STATEMENT

Standard AI-driven Dungeon Masters (DMs) in Tabletop Role-Playing Games (TTRPGs) suffer from the "Hallucination Problem".

When a single Large Language Model (LLM) manages both creative narration and underlying math, it routinely makes calculation errors, forgets character health points (HP), ignores inventory arrays, and permits spatial violations (such as passing through solid walls).

🗣️THE NATURAL LANGUAGE CHALLENGE

Why Simple Programs Fail

Natural language is rich, flexible, and ambiguous. Players expect to describe actions freely (e.g., "I slide under the table to slash the goblin's ankles"). Rigid code rules cannot understand these creative, unstructured player sentences.

Conversely, relying 100% on a neural network fails due to logic instability.

Therefore, the system requires an **LLM-based classifier** to comprehend open-ended player intentions, but must route standard mechanics to a **reliable Python backend** to calculate the mathematical rules.

🎯PROPOSED SOLUTION

We introduce Agentic-DualPath-Core, a hybrid system that separates creative story interpretation from solid mathematical rules.

The engine intercepts user texts, dynamically categorizing intents into standard actions (attacks, basic movement) and creative actions (environmental puzzle-solving).

⚙️SYSTEM ARCHITECTURE

The system executes a Two-Path Orchestrator flow, dividing actions into separate processing layers:

Player Input (Natural Language)
Intent Router (Gemini Classify / Keyword Regex)
Path A (Standard Rules)
Attacks, Movement, standard spells, items.
Python Rules Engine
Path B (Creative Rules)
Improvisation, environmental tricks, complex magic.
LLM Arbiter Layer
State Update & LLM Narrative Generation

Path A (Standard Rules - Python Engine): Standard actions are computed using hardcoded functions (dice rolls, Armor Class checks, HP subtraction). This guarantees 100% calculation accuracy and incurs zero token costs.

Path B (Creative Rules - LLM Arbiter): Improvised actions are judged by the LLM. It sets the Difficulty Class (DC) and returns a structural condition (e.g., target: `PRONE`), which Python then strictly applies to the game model.

TOON (Token-Oriented Object Notation): A highly compact custom text notation designed to pass game state data to the LLM. It reduces token size by ~40% compared to standard JSON, saving API costs and reducing response times.

🗺️NODE-BASED EXPLORATION ENGINE

To expand the system beyond combat, we implemented a structured point-crawl Exploration Engine:

1
Pass 1: Regex Filter (Zero Cost)
Filters simple commands like look, rest, status instantly.
2
Pass 2: Semantic Router (LLM)
Maps complex movement sentences to active graph exits.
3
Pass 3: Puzzle Interception
Unrecognized inputs in puzzle rooms become puzzle attempts.

Spatial Guardrails: Python verifies if a target room is connected to the current node before calling the LLM, neutralizing spatial hallucinations (e.g., moving through walls).

Infinite Lore Prevention: Separates visited and cleared states, printing descriptions exactly once to prevent repetitive generations and token overflow.

⚔️COMBAT & INITIATIVE QUEUE

Dynamic Turn Order: At the start of combat, all entities roll initiative (d20 + Physical stat). The system uses an Initiative Queue to sort combatants and loop through turns fairly.

Zone-Based Positioning: The battlefield uses grid-less zones (NEAR, MID, FAR). Attacking a target two zones away automatically incurs a mathematical disadvantage, calculated entirely in Python.
